### Their fix advice
**Smallest sound fix.** In `UpdateFeet` (SaudMotionAnimInstance.cpp:904-905), pass the guard, not the state. Use the test `UpdateBlock` already uses at lines 1092-1094:

`(Fighter->bBlocking || St == EFighterState::Block) && (St == EFighterState::Idle || St == EFighterState::Walk || St == EFighterState::Block) && Fighter->GetUpRemaining <= 0.f`

Better still, put that decision in SaudIK.h as one function of plain values (state as int, bBlocking, getting-up seconds, ground speed, clip stride, size) and have the engine call it. Then ik.cpp executes the same line the engine calls. Add a check with State = SWalk, bBlocking = true and the real Block clip's stride, plus a bites.txt sabotage that makes it read the state again.

**What it must not break.**
- The glide above `BlockShuffleMax` x size is decided ("pushed faster it still glides"). Keep the `GroundSpeed <= BlockShuffleMax * FMath::Max(Size, 0.1f)` text in `HoldsFeetMeasured` as it is: bites.txt lines 424, 425 and 430 match on it.
- A blow's push must still glide. An enemy struck with his guard up keeps `bBlocking` true while reeling, because his brain returns early when busy (FightStyleComponent.cpp:80). Hence the Idle/Walk state gate, so Hit, Down and Dash never take the block branch.
- A get-up or a turn clip showing while `bBlocking` is true must not take the branch either (`Pick` shows GetUp or the turn before Block).
- The standing, attacking and walk-stride paths, and the unmeasured-clip fallback to `HoldsFeet`, stay as they are.
- ik.cpp's existing checks at lines 2115-2143 and 2279 must still pass.
